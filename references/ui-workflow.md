# 브라우저와 Windows 기안기

## 도구 연결

브라우저 탐색은 현재 제공되는 브라우저 API를 따르고, 별도 Windows 기안기는 **computer-use 스킬 + node_repl + @oai/sky**로 조작한다. 해당 스킬의 SKILL.md와 지침/API를 먼저 읽는다. 캐시 버전 경로나 과거 창 ID를 고정하지 않는다.

- 브라우저 전용 cua의 native apps 미지원/빈 목록은 Windows 전체 프로그램이 없다는 뜻이 아니다. 별도로 제공되는 node_repl을 도구 검색으로 찾는다.
- Windows 기능 자체가 제공되지 않으면 한계를 정확히 알린다. 임의의 헬퍼 프로토콜이나 별도 자동화 우회 도구를 만들지 않는다.
- 인증서 로그인은 아래의 최초 선택과 명시적 자동 로그인 동의에 따른다. 세션 토큰·인증서 비밀번호·문서 내부 URL의 인증 값을 스킬·메모·파일에 저장하거나 별도 로그로 출력하지 않는다.

## 자동 로그인 절차

1. `https://sen.eduptl.kr`과 실제 로그인 화면을 먼저 확인한다. 이미 로그인된 경우 재인증·암호 요청 없이 진행한다.
2. 로그인 필요 시 직접/자동 선택을 한 번 묻는다. 사용자가 직접 선택하면 인증서 로그인을 맡기고 완료 후 포털 메인을 확인한다. 이미 자동 로그인 요청과 비밀번호를 준 경우 같은 허가/암호를 다시 묻지 않는다.
3. 자동에 동의했지만 비밀번호가 없으면 “이번 업무포털 로그인에 사용할 인증서 비밀번호를 알려주세요. 대화로 보내면 대화 기록에 남을 수 있습니다. 직접 입력하셔도 됩니다.”라고 요청한다. 실제 사용 가능한 보안 입력 도구가 있으면 우선한다. 비밀번호를 사용자 입력 요청의 선택지에 포함하거나 답변에서 반복하지 않는다.
4. 포털의 교육행정 전자서명 인증서 로그인 버튼을 누르고, 실제 뜬 인증서 창을 관찰한다. 브라우저 밖이면 Windows Computer Use의 현재 창/소유 팝업으로 확인한다. 현재 지원 도구와 상위 실행 제한을 따른다. 도구가 인증 창 제어를 차단하면 우회하지 않고 그 부분만 사용자에게 맡긴다.
5. 인증서가 하나로 특정되면 해당 인증서를 선택한다. 여러 개이고 사용자/기관이 불명확하면 어느 인증서인지 한 번만 묻는다. 인증서 파일이나 개인키를 추출·복사하지 않는다.
6. 확인된 인증서 비밀번호 입력란을 클릭하고 포커스를 확인한 다음 제공받은 값을 입력한다. 입력값 자체를 별도 출력하지 않는다. 인증서 변경/발급·암호 저장 기능은 누르지 않는다.
7. 이 포털의 로그인용 확인 버튼을 누른 뒤 포털 메인과 로그인된 사용자/학교를 확인한다. 다른 사이트, 문서 결재/전자서명 창에 로그인용 암호를 재사용하지 않는다.
8. 잘못된 비밀번호/인증서 오류는 그대로 알려 정정값 또는 직접 입력을 요청한다. 같은 암호를 반복 시도하지 않는다. 추가 인증이나 보안 경고가 있으면 해당 정책에 맞게 사용자에게 맡긴다.
9. 암호를 작업 결과·설정·스킬·셸 명령·파일·장기 메모에 기록하지 않는다. 작업용 메모리에서 사용한 참조도 더 이상 필요 없으면 제거한다. 도구나 대화 자체의 기록을 지웠다고 주장하지 않는다.

자동 로그인은 사용자 요청에 따라 제공하는 선택 기능이다. 실제 인증 창에서 입력과 로그인 완료를 검증하기 전에는 성공했다고 보고하지 않는다. 과거에 사용자가 직접 로그인한 사실을 자동 로그인 시험 성공으로 간주하지 않는다.

## 포털 경로

1. 지정 브라우저 또는 연결된 Chrome에서 기존 관련 탭을 재사용하거나 `https://sen.eduptl.kr`을 연다. 지정 브라우저가 불가하면 대체 브라우저 선택을 묻는다.
2. 로그인된 메인의 K-에듀파인 링크 → 문서관리 → 기안 → 공용서식 → 일반기안문 서식(결재4인,협조4인).
3. 접근성 트리가 비면 스크린샷으로 로딩/현재 화면을 확인한다. 서식 클릭 후 브라우저에 새 탭이 없으면 Windows 창을 먼저 확인한다. 클릭 반복으로 중복 기안을 열지 않는다.
4. 후속 작성에 필요한 탭은 해당 API의 인계 표시로 유지한다.

## Windows 창 선택

현재 computer-use 스킬의 초기화 지침을 따른다. 아래는 핵심 예이며 전체 API 지침을 대체하지 않는다.

```js
if (!globalThis.sky) {
  const { sky } = await import("@oai/sky");
  globalThis.sky = sky;
}
globalThis.draftingWindows = await sky.list_windows();
nodeRepl.write(JSON.stringify(draftingWindows));
```

출력에서 WXSClient.exe와 현재 일반기안문 제목이 맞는 반환 창 하나를 선택한다. 반환된 id/app으로 get_window한다. 여러 창이 있으면 실제 업무 문서를 잘못 수정하지 않도록 현재 작업을 식별한다.

## 관찰과 입력

- 관찰하고 멈춘 뒤 요소/좌표를 선택한다. 한 번 입력 또는 클릭 후 즉시 상태를 갱신한다. 이전 스크린샷 ID·좌표·요소 번호 재사용 금지.
- 제목·요지 set_value는 UIA 캐시 오류 사례가 있다. 실패 후 일부 반영 여부를 확인하고 **입력란 클릭 → 포커스 확인 → type_text**로 대체한다.
- focused_element가 ‘창’으로만 표시되면 편집란의 커서/테두리 또는 본문 필드 상태를 스크린샷으로 확인한다. 창 제목만 보고 입력하지 않는다.
- 본문 탭에서 제목 아래 본문 필드를 선택한다. 전체 창 Ctrl+A로 서식을 지우지 않는다.
- 과제카드/결재경로는 소유 팝업으로 떠서 list_windows에 없을 수 있다. get_window_state의 두 번째 이후 스크린샷도 확인한다. 해당 screenshotId와 좌표를 사용하고 수동 원점 보정은 하지 않는다.
- 스크린샷은 도구의 자동 표시로 확인한다. 검토만을 위해 이미지 데이터를 다시 디코딩/출력하지 않는다.

## 결재경로

1. 결재경로/결재경로지정 → 조직도. ‘나의결재선’이 실제 있으면 내용을 검토하여 사용할 수 있다.
2. 사용자명 검색 또는 학교 조직 선택 → 이름·소속·직위 확인 → 선택 → 추가 화살표. 화면으로 확인한 버튼만 사용한다.
3. 교무부장은 ‘부장교사’, 소속 ‘교무기획부’로, 교감은 ‘교감직무대리’로 표시될 수 있다.
4. 경로 표가 역순일 수 있다. 순번 1 기안자, 2 부장, 3 교감, 4 교장인지 확인한다. 추가하면 이전 최종자의 결재가 검토로 바뀔 수 있다.
5. 설정 창 **확인**으로 현재 기안에 반영하고 다시 검증한다. ‘나의결재선 저장’은 다른 지속 설정이므로 요청 없이 누르지 않는다.

## 첨부·완료

- 파일추가 → 파일 열기 대화상자 → 파일 이름 칸에 확정된 절대 경로 → 열기. 입력 전 포커스와 최종 파일명 확인.
- 목록에서 파일명·개수·용량·순서를 검증한다. 본문 붙임과 일치시킨다. 파일읽기 요청 시 올린 파일도 확인한다.
- 허용 형식/크기 한도는 현재 화면 기준. 임의의 압축·변환으로 원문을 훼손하지 않는다.
- 첨부 공개여부와 문서 공개구분은 별도일 수 있다. 확정된 기준과 도구 정책대로 처리하고 미확정 항목을 보고한다.
- 기본 입력 검토 중 임시저장/결재올림/발송으로 시험하지 않는다. 별도 요청으로 실행하면 결과 메시지나 문서 상태로 성공을 확인한다.
- 런타임 오류는 실패 단계를 보고한다. 과거 특정 PC의 상태 파일 삭제나 샌드박스 설정 변경을 자동 복구 단계로 넣지 않는다.

## 키워드·공개구분 화면 확인

- 결재정보 탭에서 키워드 입력을 건너뛴다. 예시 placeholder와 실제 입력값을 구분한다. 사용자가 기존 샘플 키워드 제거를 요청하면 입력란에만 포커스를 두고 선택/삭제한 뒤 빈 상태를 확인한다.
- 대국민공개여부의 비공개를 선택하고 공개제한근거의 6호를 체크한다. 이미 선택되어 있으면 토글하지 않는다. 두 상태를 함께 화면으로 확인한다.
- 기본값 변경만으로 기존 문서의 다른 근거나 사유·직원열람·정보공개포털 목록 옵션을 임의 변경하지 않는다. 새 기안에서는 별도 지시 없는 추가 조항을 임의 체크하지 않는다.
- 캡처에 다른 앱이 겹쳐 보이면 선택한 기안창을 활성화하고 다시 관찰한다. 사용자 조작 감지 시 최신 상태를 확인하며 사용자의 편집과 동시에 입력하지 않는다.
